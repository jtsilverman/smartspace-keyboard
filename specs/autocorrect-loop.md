# Autocorrect loop

Serves `specs/vision.md` milestone 5 (autocorrect judged against stock) and milestone 1
(nothing visible moves). Stacked on `specs/autocorrect-parity.md`: that spec's checks 2,
3 and 4 are the numbers this loop moves.

## Intent

An unattended loop that raises the engine's agreement with the stock recording one
change at a time. A cheap model proposes the change; deterministic code scores it and
keeps or reverts it. Jake asked for it 2026-09-12: "a focused and targeted loop that
builds the autocorrect agent ... sonnet, haiku, or even local model". Sessions on
Opus-class models closed units 1 to 4a by hand. What remains is 67 disagreeing rows
spread over three slices, the shape a hill-climb handles better than a session does.

## Non-goals

- Unit 4b, the Core ML model. The loop tunes rules and scoring; the model is its own spec.
- Widening the word tables. They are vendored data regenerated by script, and a loop
  that can add words can memorise the recording. A dictionary gap the loop reports is
  a lead for a hand pass.
- Re-recording the oracle. The recording is frozen (unit 0).
- Any file outside `engine/Sources/TypingEngine/*.swift` and
  `engine/Tests/TypingEngineTests/`. Corpora, the oracle, `EVAL.md` and `app/` are never
  the loop's to touch; the driver reverts an iteration that touches them.
- Merging. The loop commits to its own branch. Jake merges.

## Orientation

| Part | File | Owns |
|---|---|---|
| Scorer | `eval/loop/score.py` | One `swift test` run parsed into numbers: oracle dev and test per slice, typo bench, protection, suite count |
| Driver | `eval/loop/run.py` | One iteration: prompt, propose, score, keep or revert, log, commit |
| Prompt | `eval/loop/prompt.md` | What the proposer reads: objective, gates, allowed files, the dev misses, the last attempts |
| Log | `eval/loop/results.tsv` | One line per attempt: numbers before and after, verdict, the proposer's one-line summary |
| Guard benches | `engine/Tests/TypingEngineTests/TypoBenchmarkTests.swift`, `KeyboardEvalV4Tests.swift` | Moved from `app/SmartSpaceTests`, pure Swift since unit 1 |

**Non-obvious.**

- The oracle is a recording with a 6.7% instability (the drift gate). A disagreeing row
  is a lead. The guard benches, blind-authored and never read by the proposer, are the
  generalisation check, the way the blind test halves are for the punctuation engine.
- The oracle has no dev and test halves today. The loop adds them by row number parity;
  context pairs share a number, so both sentences of a pair land in the same half. The
  proposer reads dev misses only. A keep needs dev up and test not down.
- Brain, `cheap-inner-search-converges-on-gate-rejected-region`: a cheap search that
  optimises one number converges where a different gate rejects. Here the objective and
  every gate come out of the same `swift test` run and the driver applies all of them
  before a keep, so a gate-rejected region never accumulates.
- Brain, `agent-loops`: state on disk (`results.tsv` and git), a failed iteration is
  reverted rather than debugged, and the proposer never grades itself.

## Decomposition

1. **Guard benches move to the engine target.** Corpora move by `git mv`, the generator
   writes them at the new path, regeneration stays byte-identical. `app/SmartSpaceTests`
   keeps only what needs UIKit.
2. **Oracle halves.** `OracleAgreementTests` prints dev and test per slice, every dev
   miss, and the test aggregate only.
3. **Scorer.** `score.py` runs the suites once and emits JSON.
4. **Driver.** `run.py` runs N iterations in a worktree on the loop branch: keep rule,
   allowlist, log, one commit per keep authored `autocorrect-loop`.
5. **Smoke run.** One iteration on sonnet, observed end to end.

## GOAL

Jake starts the loop before bed and reads one file in the morning: a line per attempt
saying what was tried and whether the stock-agreement number rose. Every kept change is
one commit he can read and revert on its own. Nothing the loop does can move a key,
change a corpus row, or lower a guard number.

## CHECKS

1. **vision:5** the guard benches run under `swift test` and print what `xcodebuild`
   printed. `swift test --filter 'TypoBenchmarkTests|ProtectionEvalTests'`.
2. **vision:5** `python3 eval/loop/score.py` prints JSON whose oracle dev and test rows
   sum to 400, with the typo, protection and suite numbers, in under 60 seconds.
3. **vision:5** `python3 eval/loop/run.py --iterations 1` runs one iteration end to end
   and appends one line to `eval/loop/results.tsv` whose verdict is `kept` or
   `reverted`; after a revert the worktree is clean.
4. **vision:1,5** the driver reverts an iteration that touches a file outside the
   allowlist or lowers any guard number, proven by `eval/loop/test_run.py`.
5. **vision:5** a kept iteration is one commit authored `autocorrect-loop` on the loop
   branch with the before and after numbers in its message.
6. **vision:1** the driver never keeps a red suite; `swift test` stays green at or
   above 424 tests after every kept commit.

## LOOP

`python3 eval/loop/run.py --iterations N --model sonnet` from the repo root. Stops after
N iterations. Jake reads `eval/loop/results.tsv` and `git log --author=autocorrect-loop`.

## Decisions

| Decision | Reason |
|---|---|
| The proposer is `claude -p` on sonnet; a local model is a flag, not the default | The proposer must read a 330-line engine and write Swift that compiles. The local qwen models on this machine have no tool loop here |
| Keep on dev up and test not down, never on the total | Selecting on the half the proposer reads is the one leak; a test drop is the overfit signal the charter names |
| Word tables out of reach | A loop that can add words memorises the recording |
| The driver decides keep or revert in code | Unattended and it commits: the kernel's case for machine enforcement |
| One commit per kept iteration, author `autocorrect-loop` | `git log --author` audits it; one revert undoes one |
