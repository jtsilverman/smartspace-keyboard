# Eval v3: wide, code-independent benchmark

## Intent

Replace the benchmark half of the eval with corpora that cannot see our code. A new blind-authored corpus (~1,000 rows, `. ? ! , "`) generated by fresh-context agents from a scenario taxonomy -- never from engine source -- and cross-labeled by 3 independent blind annotators. Plus a one-time adjudicated relabel of the UCI real set as a new frozen set (originals untouched). Rule improvement then proceeds invariant-first: cluster misses by scenario type, name the invariant, write the general rule with one RED test per invariant, never one patch per sentence (Jake, 2026-07-27).

## Acceptance criteria

1. Blind corpus >= 900 rows after consensus filtering, stratified across the taxonomy (sentence form x register x length) with every mark represented in every register; no row authored with engine source in context (generation protocol recorded in EVAL.md).
2. Every row carries a majority label from 3 blind annotators; all-disagree rows are excluded from top-1 scoring and kept in a separate ambiguity slice scored top-2 only.
3. Label-stratified dev/test split (per-mark proportions equal across halves, unlike the seed-7 v2.1 split); test half remains aggregate-report-only.
4. Harness reports per-label AND per-scenario-type accuracy on dev, so misses cluster by invariant; shared scoring helper (no copy-paste of `score()`).
5. Contamination report: mechanical overlap check of corpus rows vs engine lexical tables, published in EVAL.md (informational, not a filter -- questions legitimately contain "what").
6. UCI relabel: 3 blind annotators re-label all 638 rows; majority wins (sender label breaks ties); lands as a NEW frozen set with provenance note; v2.1 retired from reporting, never edited.
7. Authored `corpus` demoted to rule-regression suite in EVAL.md framing; its 3 rows lifted from the real set deleted ("u say", "an amazing quote", "she said"); keeps its 90/97 gates as regression tripwires.
8. Engine baseline measured on the new blind benchmark and reported to Jake; the AC 7c ship-gate number is then set from that evidence (spec updated in a follow-up decision, not guessed now).
9. Corpus-build commits touch zero engine source files (freeze discipline from day one).

10. Typo-correction benchmark (Jake, 2026-07-27): blind-generated typo corpus (>= 300 pairs: typo -> intended word; fat-finger, transposition, dropped/doubled letters, common misspellings) scored against the REAL UITextChecker via the CorrectionEngine pipeline in the simulator test target. Metrics: corrected / left-alone / miscorrected (miscorrections are the expensive failure). Baseline reported alongside the punctuation baseline.

## Non-goals

- Editing frozen v2.1 UCI rows (relabel is a new set).
- Any engine rule change in this task (rule work is the NEXT task, driven by the new dev misses).
- ML. `: ; -` marks.

## Decisions log

- Gate number set after baseline, not before (Jake, 2026-07-27). Set from baseline: top-2 >= 80% blind test AND >= 85% real-v3 test (Jake, 2026-07-27).
- UCI noise handled by adjudicated relabel as new frozen set (Jake, 2026-07-27).
- Eval philosophy: wide not deep; corpora independent of code; invariant-first rule improvement (Jake, 2026-07-27, /loop directive).

## Decomposition

1. Harness prep (RED->GREEN): shared scoring helper + per-scenario-type reporting; taxonomy type enum in test support code.
2. Blind generation: fan-out agents author rows per taxonomy cell, label-first, no engine access; raw pool committed as data.
3. Blind cross-labeling: 3 annotator agents per row; consensus filter; ambiguity slice.
4. Assemble BlindCorpus.swift (stratified split) + contamination report; baseline run; report to Jake.
5. UCI adjudicated relabel -> RealCorpusV3.swift; v2.1 retired from reporting.
6. Authored-set demotion + EVAL.md rewrite + spec 7c note.
